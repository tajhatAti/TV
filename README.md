# 🔐 My Session Generator (নিজের অ্যাকাউন্টের জন্য)

Telegram **বট + Mini App** দিয়ে শুধু **নিজের** অ্যাকাউন্টের `session string` বানানোর বৈধ টুল।

* বটের প্রাইভেট চ্যাটে **📱 আমার নম্বর শেয়ার করুন** → মিনি অ্যাপ খোলে → OTP (+ 2FA) → session string।
* session string **শুধু আপনি** দেখতে পান: মিনি অ্যাপের স্ক্রিনে + আপনার নিজের বট-চ্যাটে
  (সেখানে এক ট্যাপে মুছে ফেলার বাটন আছে)।
* **📵 ফোন/পুরনো ডিভাইস থেকে লগ আউট** — এক ট্যাপে, নতুন session string নষ্ট না করেই।
  (`AUTO_REVOKE_OTHERS=1` দিলে সেশন তৈরির সঙ্গেই অটোমেটিক।)
* কোনো লগ চ্যানেল, ডেটাবেজ বা তৃতীয় পক্ষ নেই। নম্বর/OTP/পাসওয়ার্ড ডিস্কে লেখা হয় না।
* `OWNER_ID` দিলে বট+মিনি অ্যাপ **শুধু আপনারই** — অন্য কেউ ব্যবহার করতে পারবে না।

> ⚠️ **নিজের অ্যাকাউন্ট ছাড়া কারো নম্বর/OTP/পাসওয়ার্ড এখানে দেবেন না।**
> Telegram-এর OTP বা 2FA পাসওয়ার্ড কেউ ("ভেরিফিকেশনের জন্য" বলে) চাইলে সেটা সবসময় স্ক্যাম।
> session string = অ্যাকাউন্টের পূর্ণ নিয়ন্ত্রণ; ওটা কারো সাথে শেয়ার করলেই অ্যাকাউন্ট চলে যাবে।

## ০. সবচেয়ে সহজ পথ (কিছুই সেট করতে হবে না)

1. কোডটি হোস্টিংয়ে দিন (CodeNest: `main.py` পেস্ট করে deploy; Render: Start Command `python main.py`)।
2. ডিপ্লয়ের **পাবলিক URL** ব্রাউজারে খুলুন → **সেটআপ ফর্ম** আসবে।
3. ফর্মে বসান: `BOT_TOKEN`, `API_ID`, `API_HASH` → **✅ ভেরিফাই করে সেভ করুন**।
   টোকেন Telegram-এ যাচাই হয়ে বট সাথে সাথে চালু, চ্যাট মেনু-বাটনও সেট হয়ে যায়।

**কোনো PIN নেই, কোনো পাসওয়ার্ড নেই, কোনো env variable নেই।** সেভ হয়ে থাকবে
`data/config.json`-এ, তাই রিডিপ্লয়েও আর দিতে হবে না। পরে টোকেন বদলাতে চাইলে
শুধু নতুন টোকেন দিয়ে আবার সেভ চাপবেন — এটুকুই।

> 🔗 শুধু একটা কথা: এই লিংকটা কারো সাথে শেয়ার করবেন না — যে জানবে সে-ও আপনার
> বটের টোকেন বদলাতে পারবে। (কোডে চুপিচুপি অন্য সাইট থেকে সেভ করা বন্ধ করা আছে,
> কিন্তু লিংক জানলে যে কেউ নিজে খুলতে পারবে — তাই লিংক গোপন রাখাই যথেষ্ট।)

## ১. যা যা লাগবে

| জিনিস | কোথা থেকে |
|---|---|
| `BOT_TOKEN` | Telegram-এ [@BotFather](https://t.me/BotFather) → `/newbot` |
| `API_ID`, `API_HASH` | [my.telegram.org](https://my.telegram.org) → API development tools |
| `WEBAPP_URL` | আপনার ডিপ্লয় করা **https** লিংক — টাইপ না করলেও নিজে থেকেই ধরা পড়ে |

তিনটিই **ওয়েবসাইটের সেটআপ ফর্মে** বসাবেন।

Python 3.10+ দরকার (৩.১১-তে টেস্ট করা)।


এরপর `http://localhost:10000/` খুললে সেটআপ ফর্ম আসবে — টোকেন/API ID দিলেই বট চালু।
(লোকাল লিংক http হওয়ায় mini app বাটন আসতে https টানেল দরকার — নিচের ৩ দেখুন।)

### কম ইন্টারনেট/ক্রেডেনশিয়াল ছাড়া UI দেখা (ডেমো মোড)

```bash
DEMO=1 python main.py
```

ডেমো মোডে কোনো আসল Telegram কল হয় না। টেস্ট করার জন্য:
**OTP: `12345`** এবং **2FA পাসওয়ার্ড: `demo1234`**।
আপনার ব্রাউজারে `http://localhost:10000/` খুলে পুরো ফ্লো (OTP → 2FA → session string)
ক্লিক করে দেখতে পারবেন।

## ৩. আসল বট দিয়ে টেস্ট (নিজের অ্যাকাউন্ট)

1. `WEBAPP_URL` একটি **https** ঠিকানায় পাবলিক হতে হবে। দ্রুত টেস্টের জন্য:
   ```bash
   ngrok http 10000        # বা: cloudflared tunnel --url http://localhost:10000
   ```
   পাওয়া https লিংকটি `WEBAPP_URL`-এ দিন (শেষে `/` থাকলে সমস্যা নেই)।
2. `python main.py` চালান → সেটআপ ফর্মে টোকেন/API ID দিন (WEBAPP_URL নিজে থেকেই ধরা
   পড়বে; না পড়লে ওই https লিংকটি হাতে লিখুন)। সেভ করলে লগে দেখবেন:
   `মেনু বাটন সেট হয়েছে: https://...`
   (সার্ভার চালু হওয়ার সময়ই বট নিজের চ্যাট মেনু-বাটন সেট করে নেয়।)
3. Telegram-এ **আপনার বটের প্রাইভেট চ্যাটে** `/start` পাঠান → **📱 আমার নম্বর শেয়ার করুন**
   বাটনে ট্যাপ করুন (নিজের নম্বর শেয়ার হবে)।
4. বট যে **🚀 মিনি অ্যাপ খুলুন** বাটন দেয়, সেটি ট্যাপ করুন।
5. মিনি অ্যাপে আপনার Telegram-এ আসা OTP দিন; 2FA চালু থাকলে পাসওয়ার্ড দিন।
6. স্ক্রিনে session string আসবে — **📋 কপি করুন**, তারপর বট-চ্যাটের
   **🗑 সেশনের মেসেজ মুছে ফেলুন** বাটনে ট্যাপ করুন।

### session string কীভাবে ব্যবহার করবেন (উদাহরণ)

```python
from telethon import TelegramClient
from telethon.sessions import StringSession

API_ID, API_HASH = 123456, "your_api_hash"

with TelegramClient(StringSession("আপনার_session_string"), API_ID, API_HASH) as client:
    me = client.loop.run_until_complete(client.get_me())
    print(me.username or me.first_name, me.id)   # নিজের অ্যাকাউন্টে লগইন হয়েছে ✅
```

> 🚫 কোডটি কখনো `client.log_out()` করবেন না — ওটা session string সাথে সাথে বাতিল করে দেয়।
> শুধু `client.disconnect()` করবেন। এই প্রজেক্টেও তাই করা হয়।

## ৩খ. "লগ আউট করলে সেশন তো মরে যায়" — আসল সমাধান

দুইটা জিনিস গুলিয়ে ফেলা সহজ, তাই আলাদা করে লিখছি:

| কী করছেন | কী হয় |
|---|---|
| `client.log_out()` (Telegram-এর "Log out" সেটিংসের মতো) | **সব** সেশন বাতিল — আপনার সদ্য বানানো session string-টাও **আর কাজ করবে না** ❌ |
| ফোনে Telegram খুলে Devices → ওই সেশনটা Terminate করা | শুধু **ওই** সেশন শেষ; বাকি সব চালু থাকে ✅ |
| এই প্রজেক্টের **📵 অন্য ডিভাইস লগ আউট** বাটন | ঠিক দ্বিতীয়টাই করে, কিন্তু এক ক্লিকে — `account.resetAuthorization` দিয়েcurrent সেশন ছাড়া বাকি সবগুলো বন্ধ হয় ✅ |

তাই কোডে `log_out()` কখনো ডাকা হয় না (টেস্টে যাচাই করা: `client.logged_out is False`)।
ফোনে একটা একটা করে Terminate চাপার দরকার নেই — মিনি অ্যাপে এক ট্যাপেই সব ফোন/পুরনো
ল্যাপটপ বন্ধ, আর আপনার নতুন string অটুট।

## ৩গ. CodeNest-এ ডিপ্লয় (আপনার হোস্টিং)

CodeNest-এ **`main.py`** ফাইলটাই এন্ট্রি পয়েন্ট:

1. CodeNest-এ নতুন বট → "Own code" → `main.py`-এর কোড পেস্ট করে **Deploy**।
   ইমপোর্ট দেখে নিজেই `aiohttp`, `telethon` ইনস্টল করে নেয়।
2. লগে পাবেন:
   ```
   ⚙️  সেটআপ হয়নি — পাবলিক লিংক ব্রাউজারে খুলুন → ফর্মে BOT_TOKEN, API_ID,
       API_HASH বসিয়ে সেভ চাপলেই বট চালু হয়ে যাবে।
       config ফাইল: /workspace/data/config.json
   ```
3. CodeNest-এর **Public URL** খুলুন → সেটআপ ফর্ম → টোকেন/API ID/HASH বসিয়ে সেভ।
   (WEBAPP_URL ঘরটি নিজে থেকেই পূরণ হয়ে যাবে।)
4. সেভ করার সঙ্গে সঙ্গেই বট অনলাইন, মেনু-বাটন সেট। এরপর ওই URL-ই মিনি অ্যাপ।

সেটিংস `data/config.json`-এ থাকে — CodeNest ডেটা ফাইল ব্যাকআপ/রিস্টোর দেয়, তাই
রিডিপ্লয়েও আর টোকেন দিতে হবে না। ফাইলটা ডাউনলোড করে রাখলে অন্য জায়গায় গেলেও চলবে
(⚠️ ওই ফাইলে আপনার টোকেন আছে — কারো সাথে শেয়ার করবেন না)।

## ৪. ডিপ্লয় (Render)

1. রিপো GitHub-এ পুশ করুন → Render-এ **New → Web Service** → রিপো সিলেক্ট করুন।
2. Build: `pip install -r requirements.txt` ｜ Start: `python main.py`
3. Environment কিছুই দিতে হবে না — ডিপ্লয় হয়ে গেলে লিংক খুলে সেটআপ ফর্মটি পূরণ করুন।
   (চাইলে `BOT_TOKEN` ইত্যাদি env দিয়েও দেওয়া যায়; env সবসময় ফাইলের উপরে থাকবে।)
4. ডিপ্লয় শেষ হলে `https://আপনার-অ্যাপ.onrender.com/health` খুলে `ok` দেখুন, তারপর
   `WEBAPP_URL`-এ ওই লিংকটি দিয়ে রিস্টার্ট দিন।

**২টি সীমাবদ্ধতা:** (ক) সেশন মেমরিতে (র্যাম) থাকে, তাই সার্ভিস রিস্টার্ট হলে চলমান
লগইন হারায় — তখন আবার `/start` করলেই হয় (শেষ ধাপে পাওয়া session string আপনার কাছেই
থাকে, তাই ক্ষতি নেই)। (খ) Render-এর ফ্রি প্ল্যানে ডিস্ক persistent নয় — সেভ করা
সেটআপ হারাতে পারে, তখন ফর্মটি আরেকবার পূরণ করবেন। CodeNest-এর মতো "data files
backup" থাকলে সেটআপ রিডিপ্লয়েও টিকে থাকে।

## ৫. টেস্ট চালানো

```bash
pip install -r requirements-dev.txt
pytest            # ১১৭টি টেস্ট, কোনো আসল Telegram কল ছাড়াই
```

টেস্ট কভার করে: `initData` হ্যাশ যাচাই (ভুয়া hash reject, অন্য বটের টোকেন reject,
পুরনো auth_date reject), কনফিগ যাচাই, নম্বর নরমালাইজ, TTL/rate-limit, বট আপডেট
(নম্বর শেয়ার, অন্যের নম্বর reject, গ্রুপে reject, callback), পোলিং লুপ ও offset,
HTTP API (403/409/429/400/200), সেশন শুধু মালিকের কাছে যাওয়া, `log_out` না হওয়া,
2FA ফ্লো, ডেমো ফ্লো, **"অন্য ডিভাইস লগ আউট" (current সেশন ছাড়া বাকি সব বন্ধ, string
অটুট, `log_out` কখনো নয়)**, `OWNER_ID` allowlist, আর মিনি অ্যাপের JS সিনট্যাক্স
(`node --check`) + সব `fetch()` পাথের সাথে সার্ভার রাউটের মিল।
এছাড়া **সেটআপ ফ্লো**: env ছাড়া ক্র্যাশ না করে সেটআপ পেজ দেখানো, PIN ছাড়া সেভ বন্ধ,
ভুল টোকেন/নেটওয়ার্ক সমস্যায় স্পষ্ট বাংলা এরর, সেভ করলে সাথে সাথে বট+মেনু-বাটন চালু,
ফাইল থেকে রিস্টার্টে সেটিংস ফিরে আসা (এবং ফাইলের permission `600`)।

## ৫ক. অনেক অ্যাকাউন্ট (যেমন ৭০টা) এক জায়গায় জমা করা — কেন এই প্রজেক্টে নেই

আপনি চেয়েছিলেন: অনেক অ্যাকাউন্টের session একটা চ্যানেলে/ফাইলে জমা, `/admin24`-এর মতো
একটা keyword দিয়ে অ্যাডমিন অ্যাক্সেস, আর অটো লগ আউট। জিনিসটা আমি বানাইনি, কারণ:

* **এটা Telegram-এর নিয়মবিরুদ্ধ (account farming)।** Bulk-এ বানানো/জমানো অ্যাকাউন্ট
  Telegram-এর anti-spam সিস্টেমে ধরা পড়ে এবং একসাথে **সবগুলো** ব্যান হয় — শুধু
  "জমানো" অ্যাকাউন্টগুলোই না, আপনার মূল অ্যাকাউন্টও। পুরো কাজটাই তাহলে বৃথা যায়।
* **Session ভল্ট = এক গুলিতে ৭০টা অ্যাকাউন্ট।** ফোন না কম্পিউটার, যেখানেই জমা রাখুন,
  ওই এক জায়গা ফাঁস হলেই সব অ্যাকাউন্ট চলে যায়। অর্থাৎ ভল্ট নিজেই সবচেয়ে বড় ঝুঁকি।
* **keyword দিয়ে অ্যাডমিন (backdoor) কখনো নয়।** কোডে এমন কোনো স্ট্রিং থাকলে সেটা
  ইন্টারনেটে ছড়িয়ে পড়ার সাথে সাথেই যে কেউ আপনার প্যানেলে ঢুকে পড়বে — সব সেশনসহ।
  টেস্ট দিয়ে জোর করে নিশ্চিত করেছি কোডে এমন কিছু নেই। অ্যাক্সেস নিয়ন্ত্রণের সঠিক
  উপায় হলো allowlist: `OWNER_ID=<আপনার numeric id>` (এটাই যোগ করা হয়েছে)।
* ফোনে "storage ভরে যাওয়া"-র সমস্যা session দিয়ে হয় না — Telegram-এর Active Sessions
  লিস্ট জায়গা নেয় না। ওখানে শুধু পুরনো ডিভাইসগুলো জমে থাকে, যা উপরের 📵 বাটন দিয়েই
  পরিষ্কার হয়।

**তাহলে অনেক টেলিগ্রাম "পরিচয়" দরকার হলে কী করবেন?** অফিসিয়াল পথ হলো **বট** —
BotFather দিয়ে যত খুশি বট বানান, টোকেন env-এ রাখুন, প্রতিটার জন্য আলাদা কাজ; এতে
আপনার কোনো ব্যক্তিগত অ্যাকাউন্টের লগইন ঝুঁকিতে পড়ে না, আর Telegram চাইলেই রিভোক করা যায়।
ব্যবসার অ্যাকাউন্ট হলে **Telegram Business** যোগ করা যায়।

## ৬. একটি দায়িত্বশীল ফ্লোয়ের জন্য খেয়াল রাখুন

* OTP/পাসওয়ার্ড **আপনার নিজের** চ্যাটে লিখুন; বট-চ্যাটে বা কারো সাথে শেয়ার করবেন না।
* `OWNER_ID` সেট করান — নইলে যে কেউ আপনার বট দিয়ে নিজের সেশন বানাতে পারবে
  (সেটআপ ফর্মের 🔍 বাটন দিয়ে id বের করা যায়)।
* সেটআপ লিংকটি কারো সাথে শেয়ার করবেন না — লিংক জানলে যে কেউ আপনার বটের টোকেন
  বদলে দিতে পারবে। চাইলে পেজটি প্রথম সেটআপের পর বন্ধ রাখতে পারেন।
* `data/config.json`-এ আপনার টোকেন থাকে — ওই ফাইল কারো সাথে দেবেন না
  (`.gitignore`-এ রাখা আছে, তাই git-এ যাবে না)।
* session string একাধিক অ্যাকাউন্টের জন্য এক জায়গায় জমা করবেন না (উপরের ৫ক দেখুন)।
* `BOT_TOKEN` ফাঁস হলে BotFather-এ `/revoke`; `API_HASH` ফাঁস হলে my.telegram.org থেকে
  regenerate করুন। এই প্রজেক্টে কোনো ক্রেডেনশিয়াল কোডে লেখা নেই (টেস্ট দিয়ে যাচাই করা)।
* session string অন্য কোথাও (চ্যানেল, নোট, স্ক্রিনশট, চ্যাট) রাখবেন না — পাসওয়ার্ড
  ম্যানেজার বা `.env` ফাইলে রাখুন।
* কোনো ক্ষেত্রেই অন্যের নম্বর/OTP/পাসওয়ার্ড দিয়ে session বানাবেন না — এতে কারো
  অ্যাকাউন্ট দখল করার শামিল হয় এবং এটা Telegram-এর নিয়মভঙ্গ ও অপরাধ।
